## 3. Historia HU_EU_01_03
**Yo como Sistema, quiero garantizar que ningún paquete supere el presupuesto y avisar cuando no se pueda armar una modalidad, para que el organizador nunca vea una propuesta que no puede pagar.**
Épica: EP-02 Recomendador y cotización · Sprint 1 · Estado de validación: Con observaciones · Prioridad: Should have

Criterios de aceptación (son la fuente de verdad; los mensajes entre comillas simples son literales y los marcados «Propuesto» no se cambian en silencio):

1. Dónde: lógica del recomendador en el backend y mensajes en la pantalla 'Paquetes recomendados'.
2. Campos (entradas del cálculo):
2.1 Presupuesto.
2.2 Tipo de evento.
2.3 Número de invitados.
2.4 Catálogo vigente de servicios y precios.
3. Validación:
3.1 Un servicio es elegible si admite el tipo de evento y su capacidad cubre el número de invitados.
3.2 El costo por invitado se multiplica por el número de invitados y se redondea a COP enteros.
3.3 Cada modalidad compromete como máximo el 70 % (Ahorro), 85 % (Equilibrado) y 100 % (Premium) del presupuesto (Propuesto).
3.4 La selección es determinista: ante empate gana el menor precio y, luego, el menor identificador (Propuesto).
4. Restricción: nunca se devuelve un paquete con total mayor que el presupuesto; nunca se devuelve un paquete sin espacio, alimentación o decoración; el cálculo se verifica con una prueba de propiedad de al menos 100 entradas aleatorias sin ninguna violación.
5. Éxito: con presupuesto y oferta suficientes se devuelven las tres modalidades; si solo alcanza para algunas, se devuelven esas y se informa de las que faltan.
6. Fallo:
6.1 Presupuesto menor que el paquete Ahorro más barato: no se muestra ningún paquete y aparece 'Con ese presupuesto no es posible armar un paquete. Pruebe con un presupuesto mayor.'
6.2 Rubro obligatorio sin servicios elegibles: no se genera esa modalidad y aparece 'No hay servicios disponibles para este tipo de evento o número de invitados.'
6.3 Error inesperado: 'No fue posible completar la operación. Intente nuevamente.'

Observación de la historia: RF-REC-05 (M), RF-REC-08 (M), RF-REC-09 (S). Tarea T1. Reglas RN-01, RN-06 y RN-11 a RN-16; porcentajes y desempate Propuesto (PB-03).
Notas del analista: Dependencia: necesita el catálogo mínimo cargado (T_HU_EU_01_03_2), que también usa el listado de proveedores. Riesgo mayor del sprint: porcentajes y desempate son Propuesto (PB-03). Recorte: dejar solo Ahorro y Equilibrado si no alcanza el tiempo.
